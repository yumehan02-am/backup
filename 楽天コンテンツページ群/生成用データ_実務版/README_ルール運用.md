# ルール運用メモ

このメモは、楽天コンテンツページ自動作成のルールを別チャット、別担当者、他社環境でも再現しやすくするためのものです。現在の制作ラインを大きく変えず、ルール追加時の迷子を防ぐ目的で使います。

## ルールの3層

### 共通ルール

全社共通で守る仕様です。

- 楽天コンテンツページの構成
- TSVの並び
- 画像サイズ
- 動画サイズ
- 動画スタイル
- CSV読取
- SEO方針
- points画像の扱い
- 関連商品IDの扱い
- 商品説明は本文の焼き直しにしない
- 商品画像を確認し、商品カテゴリの誤認を防ぐ
- 企画案では `relation_depth` を使い、商品に近い企画、周辺知識、コミカルな読み物を意図的に散らす
- 同一商品群の差別化チェック
- 納品画像と動画背景は個別生成し、素材シートから切り出さない
- 画像生成後は、構造確認だけでなく納品品質チェックを行い、簡易図形や仮素材に見える画像を不採用にする

主な保存先:

- `production_workflow.md`
- `prompts/`
- `templates/`
- `scripts/`

### 店舗カスタム

店舗や会社ごとに変える仕様です。

- 対象読者
- 文体
- NG表現
- 画像の好み
- イラスト基準
- 実写の雰囲気
- ロゴ
- BGMの方向性
- 商品紹介の強さ

主な保存先:

- `custom/{brand}/`

自社用の例:

- `custom/yumehan/reference/illustration_style/character/style_notes.md`
- `custom/yumehan/reference/photo_style/lifestyle/style_notes.md`

### 特殊指示

通常フローから意図的に方向を変える指定です。

- イラスト主体
- コミカル一人称
- 失敗談風
- Q&A相談室
- 比較記事
- 実写人物なし
- 季節特化
- セール寄り
- 説明用イラスト中心
- 商品寄せイラスト
- 動画マンガ風CM
- 参照フォルダを使う

特殊指示は、なるべく `column_pattern`、`reference_mode`、`notes.md`、制作管理CSVに名前付きで残します。

## ルール追加時の原則

- チャット内だけに残さない。
- 追加した理由を短く書く。
- 共通ルールと店舗独自ルールを混ぜない。
- 他社に渡しても意味が通じる表現にする。
- 既存の制作ラインを壊す変更は避ける。
- 大きな改定が必要な場合は、先にディスカッションしてから実装する。

## 画像参照の注意

納品画像と動画背景に使う画像は、必ず1用途1画像として個別生成します。3x3グリッド、素材シート、複数画像を1枚にまとめた画像から切り出して納品画像や動画背景を作ることは禁止です。

同一ページ内の章バナー、アクセント画像、ポイント画像、動画背景は、原則として同じ文字なし元画像を使い回しません。ストーリー動画の演出として同じ場面を続ける場合を除き、役割ごとに別画像を用意します。生成後は `scripts/check_image_reuse.py` で納品画像と動画背景の近似重複を確認します。

文字入れ前の個別生成画像は、後で別ページや動画背景へ流用できる制作資産として保存してよいものです。AIで生成した文字なし画像の元データは、明らかな失敗画像を除いて `images/work/generated_originals/` に残します。一方、コンタクトシート、サムネ一覧、動画プレビュー一覧、素材シート、そこから切り出した画像は保存資産にしません。確認用に作った場合でも、納品物や次回生成の参照元にはしません。

画像制作は「個別生成 -> 元画像保存 -> 役割名で配置 -> 文字入れ・リサイズ加工 -> delivery書き出し -> 動画生成 -> 確認用プレビュー」の順序を守ります。コンタクトシート、サムネ一覧、動画プレビュー一覧は最後の確認用に限り、先に一覧を作って素材化しません。個別生成した1枚画像を納品サイズや動画サイズへ合わせてトリミングすることは許可しますが、素材シートや一覧画像から切り出すことは禁止します。

商品画像は、通常の実写風コンテンツでもイラスト主体コンテンツでも必ず確認します。目的は商品写真を再現することではなく、シルエット、丈感、ボリューム感、露出の程度、素材感、色味、使用シーンのヒントを把握し、商品カテゴリの誤認を防ぐことです。

商品画像から、正確な柄、ロゴ、商品ページ内の文字、サイズ表記、価格、モデルの顔や体型、商品写真の構図そのものは再現しません。必要に応じて `data/product_reference/` に保存し、納品画像には混ぜません。

画像・動画を作る依頼では、制作前に商品寄せレベルを提示または確認します。ユーザーがレベルを指定した場合はその指定を優先し、指定がない場合は商品カテゴリ、単一商品か商品群か、特殊形状か、商品誤認のリスク、ページ間の差別化を踏まえて推奨レベルを明記します。決めたレベルは `notes.md` または制作管理データへ残します。

商品寄せレベル:

- `level_0_confirm_only`: 商品画像は確認のみ。画像には反映しない。
- `level_1_category`: 商品カテゴリが誤認されない程度に寄せる。
- `level_2_feature`: シルエット、丈感、透け感、素材感、色味の方向性など特徴を反映する。
- `level_3_product_mood`: 実商品に近い雰囲気の生成衣服や小物を出す。ただし商品写真そのもの、モデル、ロゴ、文字、価格、完全な柄再現は避ける。
- `level_4_special_product`: 特殊形状や通常カテゴリと大きく違う商品で、商品画像を強く参照する。ただし実商品画像は合成しない。
- `level_5_actual_product_photo`: 実商品画像そのものを使う。標準では納品画像や動画背景に使わず、楽天の商品リンク可能パーツ側で扱う。

実写風画像は、標準では `reference_mode=none` とします。ユーザーが明示しない限り、`custom/` や `optional_assets/` の画像に寄せません。実写はページごとの差別化を優先します。

同一商品群のタイトル画像は、通常画像より厳しく差別化します。場所、人物の有無、人物位置、視点、余白位置、色味、小物のうち最低3つを既存ページから変えます。連続ページで同じ「背景カテゴリ + 人物位置 + 文字余白位置」の型を繰り返しません。近似重複チェックがOKでも、直近タイトル画像と必ず目視で並べ、第一印象が同じならタイトル画像を差し替えます。

同じ商品カテゴリでも、タイトル画像で主役にする要素を変えます。直前ページが使用中の場面なら、次は準備、小物、生活シーン、時間、季節、外出前後など、記事テーマに合う別の見せ方へ振ります。これは特定の商品カテゴリに限らない共通ルールです。

イラスト主体は、標準で `reference_mode=illustration_style` を使います。人物イラストの基準フォルダに `style_notes.md` がある場合、画像参照よりテキストルールを優先します。

ゆめはん用の人物入りイラストは、ユーザーから個別に別テイストの指示がない限り、`custom/yumehan/reference/illustration_style/character/` フォルダ全体と `style_notes.md` を基本テイストとして参照します。個々の画像1枚だけに寄せず、フォルダ内の基準画像全体から、線、色、人物の存在感、表情、上品さを合わせます。

商品シルエットが特殊で実写生成との齟齬が出やすい場合は、`reference_mode=product_inspired_illustration` を使います。商品画像は `data/product_reference/` に置き、納品画像には混ぜません。商品の形状や雰囲気だけを参照し、商品写真そのものや商品ページ内の文字は再現しません。

商品シルエットが特殊だが、ユーザーが「元の商品画像は使わず生成AIで作成」と指定した場合は、`reference_mode=ai_product_reference_generation` を使います。この場合、商品画像は形、丈感、露出の程度、柄の方向性、使用シーンを理解するための参照に限定し、納品画像には貼り込みません。生成プロンプトでは、通常のフィットネス水着やビキニに流れないよう、商品カテゴリ固有のシルエットを明示します。

商品寄せ指定がある場合でも、寄せる優先順位は「シルエット、丈感、露出の程度、使用シーン」を先にし、柄や色は方向性の参考に留めます。同一商品群で複数ページを作る時は、柄、色味、柄密度、明暗、無地寄りか柄物寄りかを意図的に散らします。すべてが同じ濃色花柄、同じ淡色柄、同じ配色に見える場合は、背景やポーズが違っても差別化不足です。

画像のみ再生成する場合も、ページ間の差別化は省略しません。再生成前に `ページ番号 / 役割 / 商品寄せ度 / 柄・色の方向性 / 場所 / 人物位置 / 視点 / 小物 / 避ける近似` を簡単に棚卸しし、`notes.md` または制作メモに残します。直前の修正指示だけに引っ張られて、商品寄せや同じ柄へ収束しないようにします。

## 画像品質チェック

画像生成後、動画生成とTSV出力へ進む前に、納品画像、文字なし元画像、動画背景を目視します。

ファイルがある、サイズが合っている、文字が切れていない、という構造確認だけでは不十分です。画像そのものが、実写風またはイラスト風など企画で指定したテイストに達し、楽天コンテンツページの読み物を支える見栄えになっているかを確認します。

簡易図形、棒人間、プレースホルダー、仮素材、単純なグラデーションに見える画像は不採用です。コードで作るのは文字入れ、リサイズ、トリミング、光彩、動画編集などの加工工程に限り、背景そのものは生成画像またはユーザー指定素材を使います。

チェック結果は `notes.md` に `画像品質チェック: 問題なし` または `画像品質修正: ...` の形で残します。

## 動画スタイルの注意

企画案には `video_style` を入れます。標準は `toc_cm` で、電車の吊り広告や婦人誌CMのように、コラムの問いやポイントを短く見せます。

イラスト主体で、主人公、葛藤、心の声、小さなオチがある企画は、ユーザーから「動画マンガ風」と明示されていなくても `illustrated_story_cm` を候補にします。対象になりやすい `column_pattern` は `comic_first_person`、`failure_story`、`short_story`、商品寄せイラストの主人公型です。

`illustrated_story_cm` は本格的な漫画ではなく、婦人誌の挿絵が少し動く短いコラムCMとして扱います。吹き出し、コマ割り、強い集中線、漫画記号は標準では使いません。文字は生成画像へ直接入れず、動画編集時に後入れします。

1ページに入れる動画は原則1本だけです。`toc_cm` と `illustrated_story_cm` を同じページで併用せず、企画の読み物パターンに合う方を選びます。どちらの場合も、縦長安全領域、終了ロゴ、BGM音量、MP4カバー画像埋め込みのルールは共通です。

## 制作前チェック

制作前には、`production_workflow.md` の「制作前チェックリスト」を確認します。特に以下は事故が起こりやすいため、毎回確認します。

- `reference_mode`
- 商品寄せレベル
- `video_style`
- `relation_depth`
- 同一商品群の差別化
- 画像品質チェック
- `images/delivery/` と `images/work/` の分離
- 文字なし個別生成画像と、不要な一覧画像・切り出し画像の区別
- 画像生成、加工、納品、確認用プレビューの順序
- points画像のTSV混入
- 関連商品IDの1行化
- 動画の文字切れ
- 人物イラストの年齢感
