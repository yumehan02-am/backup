# 夢販流通プロファイル仕様

## 対象業務

楽天市場、Yahoo!ショッピング、Amazon、メルカリShopsの受注データを読み込み、商品マスタでSKUを正規化し、在庫Excelへ転記する。

## 受注CSV読込ルール

### 楽天市場

- 基本SKUは `商品番号` から取得する。
- 子SKUがない商品の場合、出力位置が変わることがあるため、SKU候補が空欄または未照合の場合は代替列も確認する。
- 同一CSV内で同じ注文番号・同じSKUが複数行に分かれている場合は加算する。
- 別CSVで既に取り込んだ同一注文番号・同一SKUは重複として除外する。

### Yahoo!ショッピング

- 基本SKUは `商品番号サブ` から取得する。
- `商品番号サブ` が空欄の場合は `商品番号` を使用する。
- 同一CSV内で同じ注文番号・同じSKUが複数行に分かれている場合は加算する。
- 別CSVで既に取り込んだ同一注文番号・同一SKUは重複として除外する。

### Amazon

- SKUは `商品番号` から取得する。
- `商品番号サブ` のASINはSKU連携には使用しない。

### メルカリShops

- SKUは `original_product_id` から取得する。
- 数量は将来対応のため `quantity` も読む。
- `buyer_name` が空欄の行は未入金・未出荷として除外する。

## マスタCSVルール

- 商品名略称、親SKU、セット商品フラグは商品基本CSVから取得する。
- モールSKU連携、カラー、サイズ、子SKU構成はSKU連携CSVから取得する。
- セット商品の構成はセット構成CSVから取得する。
- セット商品は受注集計時に単品SKUへ分解する。

## Excel転記ルール

実装ファイル:

```text
profiles/yumehan/excel_rules.py
profiles/yumehan/excel_candidate_rules.py
```

Version 2 初期段階では、書き込み候補検出の入口ロジックを `excel_candidate_rules.py` に切り出す。
候補検出が使う低レベル補助関数は、移行初期段階として本体側の実績済み関数を利用する。
記入欄増設、転記パターン取得、残数行検出は引き続き本体ロジックへ委譲する。
今後、夢販流通固有のExcel候補判定変更は本体ではなく `excel_candidate_rules.py` 側へ寄せる。

- 商品ごと、または転記ページごとに在庫Excelファイル、シート名、開始列、転記パターンを持つ。
- 開始列が設定されている場合、その列を基準に候補を探す。
- 右側の倉庫用の島を誤って対象にしない。
- 空の記入欄が複数続く場合は、記入済みの島まで遡る。
- 予定行、赤字行、確保文字列は転記不可行として扱う。
- 予定行のみの島は空島扱いにする。
- 数式セルは上書きしない。
- 0数量は基本的に書き込まない。
- 候補が不明な場合は自動書込せずユーザー確認で止める。

## 同日加算ルール

- 機能設定により、同日同タイトル行へ加算できる。
- タイトルと日付の一致を基本条件とする。
- 空欄数量は0として比較する。
- 見つからない場合は設定により確認またはスキップログとする。

## 在庫アラート

- 転記した島の残数行を参照する。
- 状態は不足、在庫0、低在庫で表示する。
- 最低在庫数は商品ごとに設定する。
- マイナス最低在庫設定では、残数0を完売扱いとしてスキップし、実数とマイナス残数のみを判定対象にする。

## 出力

- 出荷集計PDFは集計リストの表示順・セグメントに合わせる。
- 商品名は `メーカー／商品名` を分割してPDF表示する。
- サイズ数量は確認しやすい形式で改行表示する。
- 在庫アラートは画面セグメント状態をPDF/CSV出力へ反映する。
