# プロファイル開発ガイド

## 目的

プロファイルは、会社・部署ごとに異なる業務ルールを本体から切り離すための単位です。

本体側はGUI、DB、Excel操作、PDF/CSV出力、ログ、バックアップなどの共通機能を担当します。
プロファイル側は、読込データの解釈やExcel在庫表の判定ルールを担当します。

## 最初に分離する対象

1. 受注CSV読込ルール
2. Excel書き込み候補検出ルール

## 将来的な構成案

```text
profiles/
  yumehan/
    profile.json
    order_import.py
    excel_rules.py
    PROFILE_SPEC.md
```

## order_import.py の責務

- CSV種類の自動判別
- 必要列の検出
- SKUの取得
- 注文番号の取得
- 数量の取得
- 未入金など除外対象の判定
- 同一CSV内と別CSV間の重複ルールの適用

本体DBへ直接書き込まず、正規化済みの注文行を本体へ返す形を基本とします。

## excel_rules.py の責務

- 開始列の解釈
- 書き込み候補セルの検出
- 転記パターンの自動取得
- 記入欄増設時のコピー範囲検出
- 予定行、確保行、赤文字行、空島などの扱い
- 候補不明時の停止理由作成

Excelファイルの保存やGUI操作は本体側に任せます。

## Version 2 初期実装

Version 2 の初期段階では、`profiles/yumehan/excel_rules.py` を窓口にします。
書き込み候補検出は `profiles/yumehan/excel_candidate_rules.py` に切り出し済みです。
記入欄増設、転記パターン取得、残数行検出などは、まだ現行の実績ある本体ロジックへ委譲します。

他社プロファイルを作る場合は、`profiles/yumehan/excel_rules.py` をコピーし、必要な関数だけ独自実装へ差し替えます。

## 禁止事項

- プロファイルからGUI部品を直接操作しない
- プロファイルからDBへ直接書き込まない
- プロファイルからExcelファイルを勝手に保存しない
- 判定不能な場合に推測で書き込まない

## 例外時の基本方針

書き込み位置やSKU解釈に確信が持てない場合は、理由を返してユーザー確認で止めます。
数量が抜け落ちることを避けるため、読込不能データは未確定リストへ回す方針です。
